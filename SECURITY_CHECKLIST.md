# 🔐 Inntris Core - Security Checklist

**FOR PRODUCTION DEPLOYMENT - CRITICAL REVIEW REQUIRED**

This checklist ensures your Inntris deployment meets security best practices for handling financial transactions and sensitive data.

---

## ✅ PRE-DEPLOYMENT SECURITY

### Credentials & Secrets Management

- [ ] **SERVER_SECRET** is 64-byte random hex (generated with `openssl rand -hex 64`)
- [ ] **MASTER_ADMIN_KEY** is 32-byte random hex (generated with `openssl rand -hex 32`)
- [ ] **BLOCKCHAIN_PRIVATE_KEY** is stored securely and never committed to git
- [ ] **DATABASE_PASSWORD** is strong (20+ characters, generated by Supabase)
- [ ] All secrets are stored in Railway/Render environment variables (not in code)
- [ ] Backup copy of all secrets stored in encrypted password manager
- [ ] `.env` and `.env.production` are in `.gitignore`

### Database Security

- [ ] Supabase **Row Level Security (RLS)** is enabled
- [ ] Database schema includes all triggers from `schemas.sql`
- [ ] Audit log modification triggers are active (test with manual UPDATE)
- [ ] Database connection uses **SSL/TLS** (`DATABASE_SSL_MODE=require`)
- [ ] Database user has **minimum required permissions** (not superuser)
- [ ] Connection pooling is configured (max 20 connections per service)
- [ ] Supabase **Point-in-Time Recovery (PITR)** is enabled (7-day retention minimum)
- [ ] Database backup schedule is configured (daily recommended)

### API Security

- [ ] **CORS** is configured with specific domains (not `*`)
- [ ] **ALLOWED_ORIGINS** includes only production domains
- [ ] Rate limiting is enabled (`RATE_LIMIT_PER_MINUTE=100`)
- [ ] Request size limit is set (`MAX_REQUEST_SIZE_MB=10`)
- [ ] API documentation (`/docs`) is accessible but doesn't expose secrets
- [ ] Health endpoint (`/health`) doesn't expose sensitive information
- [ ] Admin endpoints require `X-Admin-Key` header
- [ ] Organization endpoints require valid `X-API-Key` header

### Blockchain Security

- [ ] Deployment wallet has **dedicated purpose** (not used for other transactions)
- [ ] Wallet has **minimum balance** (0.01-0.1 ETH, no more)
- [ ] Smart contract is **verified** on BaseScan
- [ ] Only deployment wallet has `SUBMITTER_ROLE`
- [ ] Contract **pause functionality** is tested (for emergencies)
- [ ] Private key is **not** the same as personal wallet
- [ ] RPC endpoint uses HTTPS (not HTTP)

## ✅ POST-DEPLOYMENT SECURITY

### Access Control

- [ ] Master admin key is **not shared** with developers
- [ ] Organization API keys are issued per customer (1 org = 1 key)
- [ ] API keys use **prefix identification** only (first 8 chars)
- [ ] API key rotation procedure is documented
- [ ] Admin access to Railway/Render is restricted (2FA enabled)
- [ ] Supabase admin access is restricted (2FA enabled)

### Monitoring & Alerting

- [ ] Railway/Render deployment notifications are enabled (Slack/Discord)
- [ ] Database connection alerts are configured
- [ ] Blockchain wallet balance alerts are set (<0.01 ETH threshold)
- [ ] Security alerts table is monitored (check daily):
  ```sql
  SELECT * FROM security_alerts
  WHERE created_at > NOW() - INTERVAL '24 hours'
  ORDER BY severity DESC;
  ```
- [ ] Failed signature verification attempts are tracked:
  ```sql
  SELECT COUNT(*), agent_id
  FROM audit_logs
  WHERE verdict = 'signature_invalid'
    AND timestamp > NOW() - INTERVAL '1 hour'
  GROUP BY agent_id
  HAVING COUNT(*) > 10;
  ```
- [ ] Rate limit violations are monitored (Redis: `security:alerts:*`)

### Audit & Compliance

- [ ] Audit logs are **append-only** (verified with manual DELETE test)
- [ ] Merkle root updates are restricted (verified with trigger test)
- [ ] Blockchain anchoring occurs every hour (check `merkle_proofs` table)
- [ ] All financial transactions are logged (`action_type='financial_transaction'`)
- [ ] Signature verification is **strict** (`signature_valid=true` required)
- [ ] Nonce replay attacks are prevented (Redis-based nonce tracking)

### Network Security

- [ ] API is served over **HTTPS only** (Railway/Render handles this)
- [ ] No HTTP endpoints are exposed
- [ ] Database connections use **TLS/SSL**
- [ ] Redis connections are authenticated (password-protected)
- [ ] IP whitelisting is configured (optional, for high-security)

## ✅ INCIDENT RESPONSE

### If Signature Verification Attack Detected

1. **Identify affected agent**:
   ```sql
   SELECT agent_id, COUNT(*) as failed_attempts
   FROM audit_logs
   WHERE verdict = 'signature_invalid'
     AND timestamp > NOW() - INTERVAL '1 hour'
   GROUP BY agent_id
   ORDER BY failed_attempts DESC;
   ```

2. **Suspend agent** (API call):
   ```bash
   curl -X PUT https://YOUR_API_URL/admin/agents/{agent_id}/status \
     -H "X-API-Key: YOUR_ORG_API_KEY" \
     -d '{"status": "suspended"}'
   ```

3. **Notify organization** via webhook (automatic) or email

4. **Review audit logs** for the agent to determine attack vector

5. **Document incident** in security_alerts table (automatic)

### If Database Breach Suspected

1. **Immediately rotate** `DATABASE_PASSWORD` in Supabase
2. **Update** Railway/Render environment variable
3. **Redeploy** all services
4. **Review** database access logs in Supabase
5. **Check** for unauthorized schema changes
6. **Verify** audit log integrity (compare with blockchain merkle roots)

### If Blockchain Wallet Compromised

1. **Pause** smart contract (requires contract owner):
   ```bash
   cast send ANCHOR_CONTRACT_ADDRESS \
     "pause()" \
     --private-key OWNER_PRIVATE_KEY \
     --rpc-url BASE_RPC_URL
   ```

2. **Transfer remaining funds** from compromised wallet

3. **Deploy new wallet** and update `BLOCKCHAIN_PRIVATE_KEY`

4. **Grant SUBMITTER_ROLE** to new wallet

5. **Revoke SUBMITTER_ROLE** from old wallet

6. **Unpause** contract and resume anchoring

### If API Key Leaked

1. **Immediately rotate** the compromised key:
   ```bash
   curl -X POST https://YOUR_API_URL/admin/api-keys/rotate \
     -H "X-API-Key: COMPROMISED_KEY"
   ```

2. **Review all actions** performed with that key:
   ```sql
   SELECT * FROM audit_logs
   WHERE agent_id IN (
     SELECT id FROM agents WHERE org_id = 'ORG_UUID'
   )
   AND timestamp > 'LEAK_DATE'
   ORDER BY timestamp DESC;
   ```

3. **Notify organization** of the breach

4. **Provide new API key** securely (not via email)

## ✅ VULNERABILITY MANAGEMENT

### Regular Scans

Run these security tools regularly:

```bash
# Python security vulnerabilities
pip-audit

# Code security issues
bandit -r api/ mcp_server/ workers/

# Dependency vulnerabilities
safety check

# SQL injection testing
sqlmap (manual testing on staging only!)
```

### Dependency Updates

```bash
# Check for outdated packages
pip list --outdated

# Update non-breaking changes
pip install --upgrade -r requirements.txt

# Test thoroughly before deploying updates
./tests/production_test.sh
```

### Known Secure Patterns

✅ **What we do RIGHT:**
- Ed25519 signatures (not RSA)
- HMAC-SHA256 for tokens (not JWT with weak secrets)
- Nonce-based replay protection (not timestamp-only)
- Append-only audit logs (not mutable records)
- Blockchain anchoring (not just database)
- Parameterized SQL queries (not string concatenation)
- Constant-time comparisons (not `==` for secrets)

## ✅ COMPLIANCE & REGULATIONS

### Data Retention

- [ ] Audit logs retained for **7 years** (`AUDIT_LOG_RETENTION_DAYS=2555`)
- [ ] Merkle proofs are **immutable** on blockchain
- [ ] Personal data (if any) can be deleted (GDPR right to erasure)
- [ ] Organization data includes `contact_email` for compliance notices

### GDPR Compliance

- [ ] Users can request data export (manual process via admin)
- [ ] Data minimization: only collect what's necessary
- [ ] Purpose limitation: data used only for verification
- [ ] Data is encrypted in transit (HTTPS, TLS)
- [ ] Data is encrypted at rest (Supabase handles this)

### Financial Regulations

- [ ] All financial transactions are logged (immutable audit trail)
- [ ] Spending limits are enforced (`daily_limit_usd`, `per_action_limit_usd`)
- [ ] Transaction verification is cryptographically secure (Ed25519)
- [ ] Audit trail is blockchain-anchored (tamper-evident)
